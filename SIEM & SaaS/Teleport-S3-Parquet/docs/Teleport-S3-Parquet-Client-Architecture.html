Teleport S3 Parquet to Coralogix

Architecture, Lambda image, IAM, and Terraform deployment

Package: container image Architecture: x86_64 / linux/amd64 No Lambda layers

This integration is for Teleport clusters that already use External Audit Storage / Athena and land audit events as Snappy-compressed parquet in S3. An AWS Lambda function reads each new object and POSTs every event to the Coralogix Logs API.

Terraform does not create the Teleport cluster or the events bucket. Those already exist. The module creates ECR (unless you supply an image), the Lambda function, the execution role, and an optional S3 notification.

Do not run in parallel with Teleport Event Handler / OpenTelemetry export unless you want duplicate events in Coralogix.

The S3 trigger fires only for new objects. Existing files need a backfill invoke. The handler also unwraps SNS or SQS that wrap the same S3 JSON, and accepts a direct payload:

{"bucket": "your-events-bucket", "key": "events/2026-09-11/file.parquet"}

2. Why a container image (not zip, not layers)

Teleport parquet is Snappy-compressed. Reading it in Python requires pyarrow. That library is too large for a typical Lambda zip package (50 MB uploaded / 250 MB unzipped). A Lambda layer has the same unzipped size cap and must still match Python 3.12 and x86_64. This integration therefore uses a container image only and attaches no layers. Dependencies are installed inside the image.

OptionLimit / issueVerdict
Lambda zip50 MB uploaded, 250 MB unzipped; pyarrow wheel is ~50 MBNot reliable
Lambda layerSame unzipped cap; extra build that must match runtime/archDo not use
Container imageUp to 10 GB; pip install on the official AWS baseRequired

3. Image that is required

Use the official AWS Lambda Python 3.12 base. This image includes the Lambda Runtime Interface Client (RIC). The function CMD must be lambda_function.lambda_handler.

FROM public.ecr.aws/lambda/python:3.12
COPY requirements.txt ${LAMBDA_TASK_ROOT}/
RUN pip install --no-cache-dir -r requirements.txt
COPY lambda_function.py ${LAMBDA_TASK_ROOT}/
CMD ["lambda_function.lambda_handler"]

Handler flow

  1. Extract bucket and key from S3, SNS, SQS, or a direct JSON payload.
  2. Skip if the suffix is not .parquet, the prefix does not match events/, or the path contains /sessions/.
  3. s3.get_object then pyarrow.parquet.read_table.
  4. Map columns uid, session_id, event_type, user, event_time, event_data (JSON — the full Teleport audit event).
  5. POST batches of 400 to Coralogix; retry on HTTP 429 and 5xx.

5. What Terraform creates — and what it does not

ECR repositoryHolds the linux/amd64 image (unless image_uri is set)Teleport cluster

Lambda (Image)Runs the handler on each new parquet objectSession-recording pipeline
lambda:AddPermission + optional S3 notifications3.amazonaws.com may InvokeFunctionCoralogix parsers
S3 notification replace semantics. create_s3_notification = true writes a new bucket notification configuration and replaces any existing ones. Set it to false and add the trigger in the console if the Teleport bucket already notifies other systems.

manage_log_group = false (default) lets Lambda create /aws/lambda/<name> on first invoke. Set true only if the deployer can call logs:DescribeLogGroups on *.

6. IAM: deployer vs runtime

Deployer (human or CI)

Uses terraform/deployer-iam-policy.json. Replace AWS_REGION, AWS_ACCOUNT_ID, and EVENTS_BUCKET.

  • ECR create / login / push
  • IAM CreateRole / PassRole
  • Lambda create / update / invoke
  • S3 GetBucketNotification / PutBucketNotification
  • Optional DescribeLogGroups on *

Runtime role (the function)

Created by Terraform as <function_name>-role. Least privilege at invoke time only.

  • s3:GetObject on events/*
  • s3:ListBucket with prefix
  • CloudWatch Logs write
  • Optional kms:Decrypt if the bucket is SSE-KMS

9. Verify and find logs

Success payload: {"ok":true,"files":1,"events":N,"sent":N}.

aws s3 cp ./sample.parquet s3://YOUR-BUCKET/events/$(date -u +%Y-%m-%d)/sample.parquet

aws lambda invoke \
  --function-name teleport-s3-parquet-coralogix \
  --cli-binary-format raw-in-base64-out \
  --payload '{"bucket":"YOUR-BUCKET","key":"events/YYYY-MM-DD/sample.parquet"}' \
  /tmp/out.json && cat /tmp/out.json
Explore time range. Use the event time stored in the parquet (event_time / time), not “last 15 minutes”, unless the file is new. Query: applicationName:teleport AND subsystemName:audit.

Backfill existing objects

aws s3 ls s3://YOUR-BUCKET/events/ --recursive \
  | awk '{print $4}' | grep '\.parquet$' \
  | while read -r key; do
      aws lambda invoke --function-name teleport-s3-parquet-coralogix \
        --cli-binary-format raw-in-base64-out \
        --payload "{\"bucket\":\"YOUR-BUCKET\",\"key\":\"${key}\"}" /tmp/out.json
    done
